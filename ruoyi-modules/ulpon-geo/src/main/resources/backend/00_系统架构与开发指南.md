# GEO 智能管理系统 —— 系统架构与开发指南

本指南面向后端开发人员，规范 `ulpon-geo` 业务模块在若依（Ruoyi）系统架构下的目录结构、技术选型规范及与其他公共模块的依赖交互。

---

## 1. 📂 业务模块目录结构规范

开发人员在 `ruoyi-modules/ulpon-geo` 模块中创建业务代码时，应严格遵循以下包结构（以包根路径 `com.ulpon.geo` 为基准）：

```text
com.ulpon.geo
├── config                  # 模块专属配置（如线程池、RAG向量库连接配置）
├── controller              # 控制层（RESTful API 入口，处理鉴权与参数校验）
├── domain                  # 实体层
│   ├── bo                  # Business Object（业务接收/入参对象，如 xxxBo）
│   ├── vo                  # Value Object（返回给前端的展示对象，如 xxxVo）
│   └── entity              # 数据库 Entity 实体类（与 MyBatis-Plus 映射）
├── mapper                  # 数据持久层接口（MyBatis Mapper）
└── service                 # 业务逻辑层
    ├── impl                # 业务实现类
    └── client              # 第三方大模型/宣发渠道 SDK 封装客户端
```

---

## 2. 🔌 核心技术依赖与公共模块交互

由于项目采用 Ruoyi 框架开发，`ulpon-geo` 继承了父级 BOM 的公共依赖：

### 2.1 数据持久化 (`ruoyi-common-mybatis`)
* **数据库规范**：使用 **MyBatis-Plus** 进行单表 CRUD。对于多表联查（如诊断任务与明细关联），采用传统 XML 映射。
* **数据加密**：用户在宣发渠道中配置的 API Token / Password 必须在入库时加密，调用 `ruoyi-common-encrypt` 模块提供的加密注解 `@EncryptField`。
* **主键策略**：所有 `geo_` 开头的表统一使用雪花算法主键或自增主键（详见 DDL）。

### 2.2 权限与安全控制 (`ruoyi-common-security`)
* **安全校验**：在 Controller 方法上标注 `@SaCheckPermission("geo:xxx:list")` 注解进行基于 Token 的接口鉴权。
* **租户隔离**：若系统采用多租户模式，实体类需继承 `TenantEntity` 并利用 MyBatis-Plus 租户插件自动拼接 `tenant_id`。

### 2.3 消息队列与异步任务 (`ruoyi-common-core`)
* **异步处理**：批量创作、大模型诊断等耗时业务**严禁**在 HTTP 请求线程中同步执行。
* **队列规范**：在 `config` 包下配置 RabbitMQ 交换机与队列，使用 `RabbitTemplate` 发送任务，由 Worker 异步监听处理。

## 3. 🎯 接口标准响应结构

Controller 返回数据必须统一采用若依封装的返回对象 `R<T>`，对于表格分页查询使用 `TableDataInfo`。

* **普通成功响应**：
  ```java
  return R.ok("操作成功", data);
  ```
* **异常报错响应**（通过全局异常拦截器捕获）：
  ```java
  throw new ServiceException("当前账户算力余额不足", HttpStatus.HTTP_BAD_REQUEST);
  ```
