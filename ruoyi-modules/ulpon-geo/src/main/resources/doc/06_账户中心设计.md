# GEO 智能管理系统 —— 账户中心设计说明书

本模块作为后台的运营支撑系统，负责维护用户的实名认证状态、会员权益限额以及点数（AI 算力额度）与账户余额的充值和变动账单。

---

## 1. ⚙️ 功能详细说明

### 1.1 身份核验 (实名认证)
* **功能描述**：依据我国互联网信息安全法律法规，用户在使用“宣发矩阵”发布文章前，必须先进行个人身份证或企业三合一营业执照核验，解锁发布功能。

### 1.2 套餐权益
* **功能描述**：系统以套餐等级（如：免费体验版、专业运营版、企业旗舰版）为维度，控制用户的多项服务配额，包含：每日诊断上限、并发写作线程数、每日批量宣发条数限制等。

### 1.3 算力变动明细
* **功能描述**：
  * **算力点数明细**：大模型 API 调用、文章生成、Playwright 截图诊断等服务需要消耗系统内置的“算力点数”。系统提供流式变动账单。
  * **余额明细**：用户充值、购买套餐包的现金消费明细。

---

## 2. 🛠️ 技术实现方案

### 2.1 算力额度扣减防并发与防超扣设计
由于批量写作任务会开启多线程并发生成文章，如果用户余额在边缘状态，高并发极易导致“资不抵债”（超扣点数）。系统采用 **MySQL 乐观锁** 或是 **Redis 预扣减** 方案实现：

```text
高并发扣减算法 (基于 Redis 令牌桶与 MySQL 乐观锁)：

1. 批量任务启动，计算预扣总点数 = 任务数 * 单次最低消耗 (如：10篇 * 5点/篇 = 50点)
2. 检索 Redis 缓存中的用户可用点数：
   - Redis: DECRBY geo:user:points:{userId} 50
   - 判断返回值:
     - 若返回值 >= 0: 准许执行，并异步同步回写 MySQL:
       UPDATE geo_user_rights 
       SET used_points = used_points + 50, version = version + 1 
       WHERE user_id = {userId} AND points - used_points >= 50
     - 若返回值 < 0: 代表预估余额不足，将点数 INCRBY 回加，并中断任务，前端提示“算力点数不足”。
3. 任务执行完成后，根据实际消耗（如失败了 2 篇，实际退还 10点），执行 Redis 与 MySQL 的结算退还操作。
```

### 2.2 权益拦截器 (Access Interceptor)
在若依系统底层，利用 **Spring AOP 面向切面编程**，设计一个统一的 `@RequiresRights` 注解拦截器：
* 在执行 `diagnostic` (发起诊断) 或 `writing` (批量任务) 接口前，AOP 拦截器自动查询 `geo_user_rights` 表，核实用户当天的已用配额是否超限，超限直接拦截并抛出自定义异常 `RightsLimitException`。

## 3. 💾 数据库表设计 (DDL)

### 3.1 用户套餐权益表 (`geo_user_rights`)
```sql
CREATE TABLE `geo_user_rights` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id` bigint(20) NOT NULL COMMENT '关联系统用户ID (sys_user)',
  `vip_level` varchar(30) DEFAULT 'free' COMMENT '会员权益级别（free体验版 professional专业版 enterprise企业旗舰版）',
  `total_points` bigint(20) DEFAULT '0' COMMENT '账户累计充值获得的算力总点数',
  `used_points` bigint(20) DEFAULT '0' COMMENT '已消耗的算力点数',
  `daily_task_limit` int(11) DEFAULT '10' COMMENT '每日允许发起的诊断/创作任务上限',
  `concurrent_limit` int(5) DEFAULT '2' COMMENT '批量写作的最大并发线程上限',
  `expire_time` datetime DEFAULT NULL COMMENT '会员权益到期截止时间',
  `version` int(11) DEFAULT '0' COMMENT '乐观锁版本控制',
  `create_dept`      bigint(20)                       COMMENT '创建部门',
  `create_by`        bigint(20)                       COMMENT '创建者',
  `create_time`      datetime                         COMMENT '创建时间',
  `update_by`        bigint(20)                       COMMENT '更新者',
  `update_time`      datetime                         COMMENT '更新时间',
  `del_flag`         char(1)          DEFAULT '0'     COMMENT '删除标志（0代表存在 1代表删除）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uni_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户GEO服务权益限额表';
```

### 3.2 算力变动明细变动表 (`geo_billing_log`)
```sql
CREATE TABLE `geo_billing_log` (
  `log_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '账单流水ID',
  `user_id` bigint(20) NOT NULL COMMENT '系统用户ID',
  `bill_type` char(1) NOT NULL COMMENT '账单类型（1算力点数变动 2现金余额变动）',
  `trade_type` varchar(50) NOT NULL COMMENT '交易类型（charge充值 consume消费 refund退款）',
  `amount_change` decimal(10,2) NOT NULL COMMENT '变动数额（正数代表增加，负数代表减少，如点数变动 -10.00，金额变动 +100.00）',
  `current_balance` decimal(10,2) NOT NULL COMMENT '变动后的当前余额',
  `target_reference` varchar(100) DEFAULT NULL COMMENT '交易目标关联标识（如关联批量写作任务ID、充值订单号）',
  `remark` varchar(255) DEFAULT NULL COMMENT '交易内容详细说明',
  `create_dept`      bigint(20)                       COMMENT '创建部门',
  `create_by`        bigint(20)                       COMMENT '创建者',
  `create_time`      datetime                         COMMENT '创建时间',
  `update_by`        bigint(20)                       COMMENT '更新者',
  `update_time`      datetime                         COMMENT '更新时间',
  `del_flag`         char(1)          DEFAULT '0'     COMMENT '删除标志（0代表存在 1代表删除）',
  PRIMARY KEY (`log_id`),
  KEY `idx_user_bill` (`user_id`, `bill_type`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='算力变动明细与算力消耗明细流水表';
```

### 3.3 实名核验表 (`geo_user_auth`)

