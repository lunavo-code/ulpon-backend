# GEO（生成式引擎优化）智能管理系统 —— 最终菜单及功能设计方案

本方案结合若依（RuoYi-Vue-Plus）微服务框架规范，对系统的菜单结构进行扁平化改造，并对核心业务功能进行了系统性梳理。

为了降低用户的认知摩擦和操作成本，方案进行了三项核心调整：
1. **菜单结构扁平化**：移除深层嵌套的菜单，将系统层级统一控制在 **二级目录** 内，使用户查找功能更加快捷。
2. **去戏剧化命名**：将原本过于拟物化、文学色彩偏重的名称重构为严谨、直白的高效中后台管理术语。
3. **功能高度整合与收容**：
   *   将“AI智能拓词”和“规则拼词工具”收容为辅助生成工具，合并进“派生标题管理”页面，不占用左侧菜单路由。
   *   将“单篇复刻”和“批量复刻”深度整合为统一的“爆文复刻中心”菜单页面，通过同一个工作台的单篇/批量 Tab 切换操作，精简菜单层级。

### 📊 1. GEO诊断中心 (GEO Diagnostic Center)

#### 1.1 🔍 曝光度诊断
*   **功能说明**：用户对单个品牌/行业关键词发起即时诊断，系统调用无头浏览器向指定大模型提问，获取 AI 回答的提及率与倾向分析。
*   **页面布局推荐**：
    *   极极简提问框布局（与搜索引擎类似），支持多选诊断大模型平台，右侧折叠显示诊断消耗与剩余点数提示。
*   **功能推荐**：
    *   多模型异步并联查询与页面加载骨架屏。
    *   诊断时支持勾选是否输出 AI 优化建议报告。
*   **建表 SQL 大纲**：
    *   关联表：`geo_diag_task` (诊断任务表)

#### 1.2 👥 竞品能见度监控
*   **功能说明**：配置并追踪自己品牌与竞品品牌在大模型中的曝光数据对比。
*   **页面布局推荐**：
    *   顶部卡片对比指标（自身提及率、竞品最高提及率）；中部极坐标雷达图或并排柱状图展示在各模型下的曝光占比。
*   **功能推荐**：
    *   自动比对提及差值，发出竞争预警。
    *   同屏对比回答原文高亮差异。
*   **建表 SQL 大纲**：
    *   关联表：`geo_competitor_monitor` (竞品监控配置与结果表)

#### 1.3 📸 检索截图库
*   **功能说明**：管理大模型检索交互的真实网页截图，作为曝光与收录的实证。
*   **页面布局推荐**：
    *   瀑布流卡片列表，悬浮显示诊断词、时间、大模型类型，支持单卡放大预览及批量打包下载。
*   **功能推荐**：
    *   截图自动打水印（包含时间与品牌标签）。
    *   过期截图自动清理机制。
*   **建表 SQL 大纲**：
    *   关联表：`geo_snapshot_gallery` (截图快照表)

#### 1.4 📜 诊断历史记录
*   **功能说明**：追溯和对比历史的诊断操作日志，展示品牌曝光的时间线变化。
*   **页面布局推荐**：
    *   折线图展示曝光率历史走势；下方为标准的 RuoYi 查询记录列表。
*   **功能推荐**：
    *   一键对比两次历史诊断结果差异。
    *   历史导出 Excel 报告。
*   **建表 SQL 大纲**：
    *   关联表：`geo_diag_task` (诊断任务表)

#### 1.5 📉 流量与收录报表
*   **功能说明**：多维度汇总统计收录趋势、关键词排名和 GEO 漏斗数据。
*   **页面布局推荐**：
    *   标准 SaaS 数据大屏布局，包含收录总量卡片、关键词大模型排名列表和流量趋势面积图。
*   **功能推荐**：
    *   收录比率变化周环比统计。
    *   高权重引流渠道源站排行。
*   **建表 SQL 大纲**：
    *   关联表：`geo_data_report` (数据报表汇总表)

### 🎯 2. 策略词库中心 (Keyword Strategy Center)

#### 2.1 🏷️ 核心词管理 (Core Keyword Management)
*   **业务说明**：集中维护管理用作 GEO 优化的核心源词与公司/品牌名称的映射。它是后续 AI 自动生成文章标题、爆文复刻、批量文章写作以及可见度诊断的顶层维度和核心实体。
*   **字段界定与设计**：
    *   `keyword_id` (`bigint`)：主键ID（雪花ID）。
    *   `keyword` (`varchar(150)`)：**核心关键词**（必填。如：`CRM系统`，用作大模型检索和文章SEO优化的核心触发词）。
    *   `company_name` (`varchar(150)`)：**公司/品牌名称**（必填。如：`织信软件`，用作提及率评估与回答意图转化的大纲主标）。
    *   `keyword_type` (`char(1)`)：分类标签（`1`品牌词，`2`产品词，`3`行业词，`4`竞品词。使用若依字典 `sys_geo_keyword_type` 维护）。
    *   `status` (`char(1)`)：启用状态（`0`启用，`1`停用，便于批量写作任务和定时诊断时过滤）。
    *   `remark` (`varchar(500)`)：备注说明。
*   **页面布局推荐**：
    *   **检索过滤栏**：支持通过 `关键词`（模糊匹配）、`公司/品牌`（模糊匹配）、`分类标签`（下拉选择）进行一键过滤。
    *   **操作工具栏**：支持若依标准的 `新增`、`修改`、`删除`，以及 `导入（Excel批量上传）` 和 `导出` 功能。
    *   **表格网格 (Grid)**：显示核心词、关联公司名、分类标签、启用状态、创建者与创建时间。
    *   **操作列设计**：
        1.  `修改` / `删除`；
        2.  `🪄 生成标题`（点击后直接在页面内呼出**辅助拓词工具弹窗**，基于当前核心词和公司名自动触发 AI 批量标题生成或规则拼词组装，生成出的标题一键保存至“2.3 派生标题管理”中）。
*   **建表 SQL 设计**：
    ```sql
    CREATE TABLE `geo_keyword` (
      `keyword_id` bigint(20) NOT NULL COMMENT '主键ID',
      `keyword` varchar(150) NOT NULL COMMENT '核心关键词',
      `company_name` varchar(150) NOT NULL COMMENT '公司/品牌名称',
      `keyword_type` char(1) DEFAULT '2' COMMENT '关键词分类(1品牌词 2产品词 3行业词 4竞品词)',
      `status` char(1) DEFAULT '0' COMMENT '状态(0启用 1停用)',
      `del_flag` char(1) DEFAULT '0' COMMENT '删除标志(0代表存在 2代表删除)',
      `create_dept` bigint(20) DEFAULT NULL COMMENT '创建部门',
      `create_by` bigint(20) DEFAULT NULL COMMENT '创建者',
      `create_time` datetime DEFAULT NULL COMMENT '创建时间',
      `update_by` bigint(20) DEFAULT NULL COMMENT '更新者',
      `update_time` datetime DEFAULT NULL COMMENT '更新时间',
      `remark` varchar(500) DEFAULT NULL COMMENT '备注',
      PRIMARY KEY (`keyword_id`),
      UNIQUE KEY `idx_kw_company` (`keyword`,`company_name`,`del_flag`)
    ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='GEO核心词库管理表';
    ```

#### 2.2 📊 搜索热度指数
*   **功能说明**：查询关键词在传统引擎与大模型检索中的搜索指数和竞争度。
*   **页面布局推荐**：
    *   搜索热度趋势双折线对比图（传统搜索指数 vs 大模型检索频次）。
*   **功能推荐**：
    *   实时热词搜索飙升预警。
    *   指数变动导出。
*   **建表 SQL 大纲**：
    *   关联表：`geo_keyword_index` (热度指数记录表)

#### 2.3 💡 派生标题管理 (Derived Title Management)
*   **业务说明**：集中管理和维护由核心关键词所生成、衍生出的文章标题与口语化提问。页面中内置 **“AI智能拓词弹窗”** 与 **“规则拼词工具弹窗”** 作为辅助生成工具。此页面是后续批量写作任务的直接选题源。
*   **辅助生成工具（弹窗/辅助组件）说明**：
    *   **辅助工具A：AI智能拓词弹窗**：调用大模型拼接 Prompt，输入 `{keyword}` 与 `{company_name}`，自动拓展输出多款意图问答与测评标题（如：*中小企业好用的CRM系统推荐哪些？织信软件真实评测*）。
    *   **辅助工具B：规则拼词工具弹窗**：采用卡片式的 A-F 区多文本框输入界面，基于前缀、形容词、主词、后缀等设定执行笛卡尔积运算，批量拼装长尾句。
*   **字段界定与设计**：
    *   `derived_id` (`bigint`)：主键ID（雪花ID）。
    *   `keyword_id` (`bigint`)：关联核心词ID（外键关联 `geo_keyword` 表，以此关联品牌词和行业主轴）。
    *   `derived_question` (`varchar(500)`)：**生成的文章标题/用户提问内容**（必填。如：`中小企业好用的CRM系统推荐哪些？织信软件真实评测`）。
    *   `title_type` (`char(1)`)：标题风格分类（`1`口语提问，`2`中立对比，`3`痛点场景，`4`避坑指南，`5`自定义。使用若依字典 `sys_geo_title_type` 维护）。
    *   `status` (`char(1)`)：创作状态（`0`待创作，`1`已创作，`2`已禁用）。
*   **页面布局推荐**：
    *   **检索过滤栏**：支持按核心词（支持下拉联想检索）、生成标题名称（模糊查询）、状态分类（已创作/待创作）、标题风格类型进行精准过滤。
    *   **操作工具栏**：支持 `批量删除`、`一键批量创建智写任务`。顶部提供快捷按钮：`🪄 AI自动拓词生成` / `🛠️ 规则拼词生成`，点击分别呼出对应的生成器弹窗。
    *   **数据表格 (Grid)**：显示核心词、关联公司/品牌名、生成的标题/派生问题、风格分类、创作状态、创建时间。
    *   **行内操作列**：
        1.  `修改` / `删除`；
        2.  `✍️ 去智写`（带入该标题跳转至AI创作，直接进行单篇精修）；
        3.  `🔍 查收录`（快速测试该提问在指定大模型中的收录现状）。
*   **建表 SQL 设计**：
    ```sql
    CREATE TABLE `geo_keyword_derived` (
      `derived_id` bigint(20) NOT NULL COMMENT '主键ID',
      `keyword_id` bigint(20) NOT NULL COMMENT '关联核心词ID',
      `derived_question` varchar(500) NOT NULL COMMENT '生成的文章标题/用户提问内容',
      `title_type` char(1) DEFAULT '1' COMMENT '标题类型(1口语提问 2中立对比 3痛点场景 4避坑指南 5自定义)',
      `status` char(1) DEFAULT '0' COMMENT '状态(0待创作 1已创作 2已禁用)',
      `del_flag` char(1) DEFAULT '0' COMMENT '删除标志(0代表存在 2代表删除)',
      `create_dept` bigint(20) DEFAULT NULL COMMENT '创建部门',
      `create_by` bigint(20) DEFAULT NULL COMMENT '创建者',
      `create_time` datetime DEFAULT NULL COMMENT '创建时间',
      `update_by` bigint(20) DEFAULT NULL COMMENT '更新者',
      `update_time` datetime DEFAULT NULL COMMENT '更新时间',
      `remark` varchar(500) DEFAULT NULL COMMENT '备注',
      PRIMARY KEY (`derived_id`),
      KEY `idx_keyword_id` (`keyword_id`)
    ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='GEO派生词与自动标题管理表';
    ```

### 🧠 3. 品牌资产配置 (Brand Assets Config)

#### 3.1 📖 品牌知识库 (Brand Knowledge Base)
*   **业务说明**：集中存储和维护企业背景、品牌价值以及具体商品的结构化信息（特色、卖点、介绍）。该知识库是 AI 批量创作的“事实底座”，通过将真实的商品特色与推广卖点强力注入大模型 Prompt，能生成完全符合商品调性、且没有虚假幻觉的推广稿件。
*   **字段界定与设计**：
    *   `knowledge_id` (`bigint`)：主键ID（雪花ID）。
    *   `company_name` (`varchar(150)`)：**公司/企业名称**（必填，如：`织信科技`，方便与核心词库、自媒体账号进行企业级归口）。
    *   `brand_name` (`varchar(150)`)：**品牌名称**（非必填，如：`织信软件`，对于多品牌运作企业可在此细分）。
    *   `item_name` (`varchar(150)`)：**具体商品/服务名称**（必填，如：`织信微搭低代码平台`）。

#### 3.2 🔄 官网自学习同步 (Website Auto-learning Sync)
*   **业务说明与设计思路**：
    与“官网SEO同步”将系统内容向外推送的逻辑类似，本页面解决的是“如何将官网产生的新闻、产品特性等数据自动、安全地回收学习”的问题。本系统采用 **“图文反向抓取/接收适配器”** 架构，提供三种自学习同步模式，并且支持**直接复用已配置的官网站点凭证（`site_id`）**以简化操作：
    1.  **模式一：传统爬虫抓取 (Web Crawler)**：针对没有接口的传统网站，配置 Cron 定时任务，后端通过爬虫抓取网页 HTML，并通过配置 CSS 选择器过滤导航栏和页脚，智能清洗出主体正文。
    2.  **模式二：API 定时拉取 (API Pull)**：对于提供查询 API 的 CMS 网站，定时去请求对方的新闻列表接口，支持配置 HTTP Headers（可直接复用 `geo_website_config` 的凭证），利用 JSONPath 表达式（如 `$.posts[*].content`）批量提取正文及产品参数。
    3.  **模式三：Webhook 被动接收 (Webhook Push)**：本系统向外暴露一个标准的 API 被动接收端点（如 `/api/geo/webhook/learn`）。企业可以在官网 CMS 系统（如 WordPress 发布新文章时）配置 Webhook，一有内容更新就主动 POST 给本系统，系统自动解析并存入知识库。
*   **字段界定与设计**：
    *   `sync_id` (`bigint`)：主键ID（雪花ID）。
    *   `site_id` (`bigint`)：**关联的已配置官网站点ID**（可为空，关联 `geo_website_config` 表。关联后可自动复用其主域名、发文 API 秘钥及 Headers，无需重复配置验证信息）。
    *   `sync_name` (`varchar(150)`)：**同步任务名称**（必填，如：`官网产品新闻自学习`）。
    *   `sync_mode` (`char(1)`)：**同步模式**（`1` 传统爬虫抓取, `2` API定时拉取, `3` Webhook被动接收）。
    *   `source_url` (`varchar(500)`)：爬虫入口 URL / API 拉取直链地址。
    *   `cron_expression` (`varchar(100)`)：**定时同步周期**（如每天零点 `0 0 0 * * ?`。Webhook被动模式下无需此参数）。
    *   `crawler_selectors` (`varchar(500)`)：**正文提取 CSS 选择器**（爬虫模式下必填，如：`.article-content, #main-text`，用于提取正文）。
    *   `response_content_path` (`varchar(150)`)：**内容提取 JSONPath 表达式**（API模式下必填，如 `$.data.list[*].content`）。
    *   `status` (`char(1)`)：启用状态（`0`正常，`1`停用）。
*   **页面布局推荐**：
    *   **同步排程看板**：上方展示总体自学习统计卡片（已累计自学习篇数、提取有效字符数、上次同步时间）。下方为同步排程列表。
    *   **学习测试弹窗**：在新建或修改配置时，提供一键 `⚡ 模拟自学习` 按钮，展示抓取解析后的纯文本预览与切片，确保抓取规则配置无误后再入库。
*   **建表 SQL 设计**：

### 🚀 5. 矩阵宣发中心 (Publishing Matrix)

#### 5.1 🎯 官网SEO同步 (Website SEO Sync)
*   **业务说明与架构设计**：
    由于不同企业使用的官方网站系统（CMS）多种多样，有的使用开源系统（如 WordPress, PbootCMS, EyouCMS 等），有的则是公司自研的专用 API。因此，本系统采用 **“可插拔驱动适配器 (Adapter Pattern)”** + **“自定义 Webhook 载荷映射器 (JSON Mapper)”** 架构进行设计，彻底解决不同 API 的兼容问题：
    1.  **内置标准 CMS 驱动**：出厂预设标准接口驱动，支持 WordPress 官方 REST API，以及针对 PbootCMS/EyouCMS 等国内主流 CMS 提供官方“免开发 PHP 对接适配脚本文件（用户直接下载并扔进网站根目录即可免密对接）”。
    2.  **自定义 Webhook 映射器**：对于完全自研接口的企业，支持其在 UI 界面自定义配置其 API 的 `HTTP Headers`、`Body 请求体 JSON 模版`（支持占位符替换，如 `{title}`, `{content}`），以及配置 `回执直链提取 JSONPath`（如 `$.data.articleUrl`，便于系统提取发布成功的文章真实链接并自动提交百度/谷歌爬虫收录）。
*   **字段界定与设计**：
    *   `site_id` (`bigint`)：主键ID（雪花ID）。
    *   `site_name` (`varchar(150)`)：**站点自定义名称**（必填，如：`织信科技中文官网`）。
    *   `site_url` (`varchar(250)`)：**网站主域名**（必填，如：`https://www.company.com`）。
    *   `cms_type` (`char(1)`)：**对接接口类型**（`1` WordPress标准API, `2` PbootCMS专用脚本, `3` EyouCMS专用脚本, `4` 自定义通用 Webhook）。
    *   `api_url` (`varchar(500)`)：**对接接口地址**（必填，指发文 API 的完整直链路径）。
    *   `http_headers` (`text`)：**自定义请求头**（选填，用于自定义 Webhook 鉴权，存储 JSON 字符串如 `{"Authorization": "Bearer tokenxxx"}`）。
    *   `body_template` (`text`)：**请求体 JSON 模版**（自定义 Webhook 模式下必填。支持参数占位符，如：`{"title": "{title}", "text": "{content}", "cate_id": "{target_cat_id}"}`）。
    *   `response_url_path` (`varchar(150)`)：**回执链接 JSONPath**（自定义 Webhook 模式下必填。系统用它来提取响应 JSON 中的发文直链，如：`$.data.url`）。
    *   `target_cat_id` (`varchar(100)`)：映射的对方栏目ID（如发往对方网站的“行业新闻”栏目）。
    *   `publish_status` (`char(1)`)：默认发布状态（`0`直接发布，`1`存为草稿）。
    *   `status` (`char(1)`)：启用状态（`0`正常，`1`停用）。
*   **页面布局推荐**：
    *   **站点对接配置页**：左边为已对接的官网列表，右边为详细表单。当选择 `4 自定义通用 Webhook` 时，表单动态展示 `HTTP Headers`、`Body 模版` 和 `JSONPath 解析规则` 输入框，并配有一键 `🔌 对接连通性测试` 按钮。
*   **建表 SQL 设计**：
    ```sql
    CREATE TABLE `geo_website_config` (
      `site_id` bigint(20) NOT NULL COMMENT '站点配置ID',
      `site_name` varchar(150) NOT NULL COMMENT '站点自定义名称',
      `site_url` varchar(250) NOT NULL COMMENT '网站主页面域名',
      `cms_type` char(1) NOT NULL DEFAULT '1' COMMENT '接口类型(1WordPress 2PbootCMS 3EyouCMS 4自定义Webhook)',
      `api_url` varchar(500) NOT NULL COMMENT '发文API接口地址',
      `http_headers` text DEFAULT NULL COMMENT '自定义HTTP请求头(JSON存储)',
      `body_template` text DEFAULT NULL COMMENT '请求体JSON模版(支持变量替换)',
      `response_url_path` varchar(150) DEFAULT NULL COMMENT '回执链接提取JSONPath',
    ```
