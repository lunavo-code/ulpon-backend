## 1. 多租户数据隔离总体设计

系统采用**逻辑隔离（共享数据库 + tenant_id 隔离字段）**方案，实现不同企业数据的绝对隔离。

### 1.1 数据隔离分类
为了保证系统公共配置的共享以及业务数据的安全，表按以下规则分类：
* **隔离业务表**：强制添加 `tenant_id varchar(20)`，所有的 `geo_` 业务表以及 `sys_user`, `sys_role`, `sys_dept` 均在此列。
* **共享配置表（白名单表）**：不加 `tenant_id`，如 `sys_menu`, `sys_dict_type`, `sys_dict_data`, `sys_config` 等，全局共享只读。

### 1.2 向量数据库（RAG）的物理隔离
大模型的向量数据（Milvus/PGVector）不受关系型数据库 MyBatis-Plus 插件约束，**必须手动在 Payload 中注入租户标记，在相似度检索时强加布尔条件过滤**，从物理上隔绝租户间的“知识跨越泄露”：
* **写入向量时**：在 Payload 中注入 `metadata.put("tenantId", TenantHelper.getTenantId())`。
* **检索向量时**：强制构造 Filter 表达式：`tenantId == '当前租户ID'`。

## 2. 多租户免选择登录机制

为了避免在登录页面强迫用户输入或下拉选择“租户编码”，我们采用 **“手机号/邮箱作为全局唯一账号”** 的登录模式。

### 2.1 方案对比与商业决策

| 方案模式 | 运作原理 | 适合小程序/App | 综合评估 |
| :--- | :--- | :--- | :--- |
| **方案一：全局唯一账号模式** (落地标准) | 使用手机号/邮箱作为全局唯一标识，通过身份字段反向检索并锁定 `tenant_id`。 | 🔴 极佳（支持微信手机号授权一键登录） | **首选**。开发成本低，用户体验最好。 |
| **方案二：二级域名识别模式** | 根据浏览器三级域名（如 `compA.geosystem.com`）解析租户。 | ❌ 极差（受限微信小程序域名白名单规范） | 适合纯网页端 B2B 场景。 |
| **方案三：账号后缀组合模式** | 用户登录输入 `admin@compA`。 | 🟡 一般（需用户手动输入后缀） | 体验略显臃肿。 |
| **方案四：双因子分步登录模式** | 先输手机号检索租户，再根据租户弹出密码框。 | 🟡 一般（小程序端交互繁琐） | 交互极佳但开发量过大。 |

### 2.2 租户管理员账号的生成规则
由于取消了全局统一的 `admin` 简写用户名登录，各租户管理员账号生成规则如下：
1. 每个新租户入驻时，系统自动为其生成唯一的 `admin` 账户名称，但**该名称不作为登录凭证**。
2. 租户管理员的**唯一登录凭证为他注册时填写的手机号或企业邮箱**（如 `13800000000`）。
3. 该用户记录的 `sys_user` 角色（Role）绑定为 `admin`（超级管理员）。

## 3. A/B 双方案切换与演进设计

为了降低前期开发门槛，同时为后续产品升级留出空间，系统设计了 **A（逻辑多账号）** 与 **B（统一账号中台+成员关联）** 两套演进方案。

```text
【演进路线】
项目上线初期 ➔ 方案 A (低侵入，1天联调完毕，手机号在sys_user中重复，登录后弹框选企业)
项目成熟期   ➔ 方案 B (升级改造，手机号剥离至sys_user_auth，支持登录后免密一键切换企业)
```

### 3.1 方案 A：逻辑多账号模式 (前期上线方案)
* **思想**：每个租户下有一条相同的手机号记录。在登录时，如果发现该手机号对应多个租户，系统将匹配的租户列表返回，前端弹窗让用户选择要进入的企业。
* **业务流程**：
  ```text
  用户输入手机号 ➔ 后端查询 sys_user ➔ 发现关联 Tenant A 和 Tenant B 
  ➔ 后端返回“临时企业列表 + 临时凭证 tempToken” ➔ 前端弹出“选择企业”模态框 ➔ 用户点击“企业 A”
  ➔ 前端携带“tempToken + 选择的租户ID”二次请求 ➔ 后端校验通过，发放正式 Sa-Token ➔ 成功登录
  ```

### 3.2 方案 B：统一用户中台 + 租户成员切换模式 (后期升级方案)
* **思想**：将“账号身份（Account）”与“企业成员（Member）”完全解耦。一个手机号在系统中只有一条身份数据和密码。
* **🔑 若依权限适配机制 (Sa-Token loginId 映射)**：
  在 Sa-Token 执行 `StpUtil.login(loginId)` 时，传入的 `loginId` **不再是全局账号主键 `auth_id`，而是成员关系主键 `member_id`**。因为若依原有的 `sys_user_role`、`sys_user_post` 等权限表全部与 `userId`（在方案B中物理映射为 `member_id`）绑定，此设计可使**若依底层的全部权限、角色和数据过滤代码零改动运行！**

## 5. 后端 Java 核心类与接口实现

### 5.1 租户上下文持有者 (`TenantHelper.java`)
```java
package com.ruoyi.common.core.helper;

import cn.dev33.satoken.session.SaSession;
import cn.dev33.satoken.stp.StpUtil;

public class TenantHelper {
    private static final ThreadLocal<String> TEMP_TENANT_ID = new ThreadLocal<>();

    public static String getTenantId() {
        String tempId = TEMP_TENANT_ID.get();
        if (tempId != null) return tempId;
        try {
            if (StpUtil.isLogin()) {
                SaSession session = StpUtil.getTokenSession();
                if (session != null) {
                    Object tenantId = session.get("tenantId");
                    return tenantId != null ? tenantId.toString() : "000000";
                }
            }
        } catch (Exception e) {}
        return "000000";
    }

    public static void setTempTenantId(String tenantId) { TEMP_TENANT_ID.set(tenantId); }
    public static void clear() { TEMP_TENANT_ID.remove(); }
    
    // 执行忽略拦截器的包装方法
    public static <T> T ignore(java.util.concurrent.Callable<T> callable) {
        // 在此可注入临时绕过多租户过滤器的标志位，业务完成后清除
        try {
            return callable.call();
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}
```

### 5.2 MyBatis-Plus 租户插件配置 (`MybatisPlusConfig.java`)

@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new TenantLineInnerInterceptor(new TenantLineHandler() {
            @Override
            public Expression getTenantId() {
                return new StringValue(TenantHelper.getTenantId());
            }
            @Override
            public String getTenantIdColumn() { return "tenant_id"; }
            @Override
            public boolean ignoreTable(String tableName) {
                return Arrays.asList("sys_menu", "sys_dict_type", "sys_dict_data", "sys_config").contains(tableName);
            }
        }));
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}

### 5.3 方案 A 核心登录接口
```java
// 接口 1: 手机号登录校验
@PostMapping("/login-by-phone")
public R<?> loginByPhone(@RequestBody PhoneLoginBo bo) {
    List<SysUser> users = TenantHelper.ignore(() -> sysUserService.selectListByPhonenumber(bo.getPhonenumber()));
    if (CollUtil.isEmpty(users)) return R.fail("账号或密码错误");
    
    List<SysUser> matchedUsers = users.stream()
        .filter(u -> BCrypt.checkpw(bo.getPassword(), u.getPassword())).collect(Collectors.toList());
    if (CollUtil.isEmpty(matchedUsers)) return R.fail("账号或密码错误");
    
    if (matchedUsers.size() == 1) {
        return R.ok(generateToken(matchedUsers.get(0)));
    }
    
    String tempToken = IdUtils.fastSimpleUUID();
    RedisUtils.setCacheObject("temp_login:" + tempToken, matchedUsers, Duration.ofMinutes(5));
    
    List<Map<String, String>> tenantList = matchedUsers.stream().map(u -> {
        Map<String, String> map = new HashMap<>();
        map.put("tenantId", u.getTenantId());
        map.put("companyName", u.getCompanyName());
        return map;
    }).collect(Collectors.toList());
    
    Map<String, Object> result = new HashMap<>();
    result.put("tempToken", tempToken);
    result.put("tenantList", tenantList);
    result.put("needSelectTenant", true);
    return R.ok("请选择登录企业", result);
}

// 接口 2: 选择租户后确认登录
@PostMapping("/confirm-login")
public R<?> confirmLogin(@RequestBody ConfirmLoginBo bo) {
    List<SysUser> matchedUsers = RedisUtils.getCacheObject("temp_login:" + bo.getTempToken());
    if (CollUtil.isEmpty(matchedUsers)) return R.fail("登录凭证已失效");
    
    SysUser targetUser = matchedUsers.stream()
        .filter(u -> u.getTenantId().equals(bo.getTenantId())).findFirst().orElse(null);
    if (targetUser == null) return R.fail("非法的租户ID");
    
    RedisUtils.deleteObject("temp_login:" + bo.getTempToken());
    return R.ok(generateToken(targetUser));
}
```

### 5.4 方案 B 核心切换接口与权限重载
```java
@PostMapping("/switch-tenant")
public R<TenantSwitchVo> switchTenant(@RequestBody SwitchTenantBo bo) {
    Long authId = LoginHelper.getAuthId();
    SysTenantMember targetMember = TenantHelper.ignore(() -> 
        tenantMemberService.selectByAuthIdAndTenantId(authId, bo.getTargetTenantId())
    );
    if (targetMember == null || "1".equals(targetMember.getStatus())) {
        return R.fail("您无权访问该企业空间");
    }
    
    // 动态修改 Sa-Token 缓存中的当前租户 ID 与当前租户关联的 member_id (即 userId)
    SaSession tokenSession = StpUtil.getTokenSession();
    tokenSession.set("tenantId", bo.getTargetTenantId());
    tokenSession.set("userId", targetMember.getMemberId()); 
    
    TenantSwitchVo vo = new TenantSwitchVo();
    vo.setTenantId(bo.getTargetTenantId());
    vo.setPermissions(permissionService.getMemberPermissions(targetMember));
    vo.setMenus(menuService.selectMenuTreeByMemberId(targetMember.getMemberId()));
    return R.ok("空间切换成功", vo);
}
```

## 6. 前端集成与无感切换交互设计 (Vue3 + Pinia)

前端接收到接口 5.4 返回的数据后，重置 Vue-Router 动态路由并完成无缝切换：

```javascript
import { defineStore } from 'pinia'
import router, { resetRouter } from '@/router'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: '',
    tenantId: '',
    permissions: [],
    menus: []
  }),
  actions: {
    async switchWorkspace(targetTenantId) {
      const res = await api.post('/system/tenant/switch', { targetTenantId })
      if (res.code === 200) {
        this.tenantId = res.data.tenantId
        this.permissions = res.data.permissions
        
        // 重置动态路由，重新向前端路由器注入新菜单，实现空间无感刷新
        resetRouter()
        const accessStore = useAccessStore()
        const dynamicRoutes = accessStore.generateRoutes(res.data.menus)
        dynamicRoutes.forEach(route => router.addRoute(route))
        
        router.push('/')
      }
    }
  }
})
```

## 7. 边界异常与安全风控策略

### 7.1 用户在不同企业状态独立的控制
* **策略**：在 `/switch-tenant` 逻辑中必须强校验 `sys_tenant_member.status`。如果目标租户的成员状态为“1(禁用)”，即使其全局 `sys_user_auth` 正常，也直接拒绝切换。

### 7.2 RAG 向量数据的隔离完整性
* **策略**：封装向量数据库的 Search 模块，在注入 Context 前校验 `tenantId == currentTenantId`，防止通过伪造相似度向量进行越权攻击。

### 7.3 从方案 A 平滑过渡到方案 B 数据迁移步骤
当系统需要从方案 A 重构升级为方案 B 时，按以下顺序执行迁移：
1. **提取全局账号**：将 `sys_user` 表中的不同手机号提取插入 `sys_user_auth`，密码直接沿用原有的 BCrypt 密文。
2. **迁移成员关系**：将 `sys_user` 的记录整体插入 `sys_tenant_member`，并令 `member_id` 值强制等于原 `user_id` 的数值，`auth_id` 关联 `sys_user_auth` 的新主键。
3. **完成无损迁移**：由于原 `user_id` 与新 `member_id` 数值完全对应，**所有的历史数据关联（角色、岗位、以及历史日志中的 `create_by` 等）无需任何改动，即完成无损平滑升级**。
