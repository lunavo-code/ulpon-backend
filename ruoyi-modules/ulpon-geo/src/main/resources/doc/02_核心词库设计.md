# GEO 智能管理系统 —— 核心词库设计说明书

本模块负责 GEO/SEO 优化中最基础也是最重要的**策略词汇筹备**。支持传统搜索热度查询、AI 对话式长尾词语义拓展、规则拼装词矩阵，并进行统一管理。

---

## 1. ⚙️ 功能详细说明

### 1.1 词库管理 (词库管理)
* **用户路径**：用户可以创建不同的词库分类（如“通用品牌词”、“核心竞品词”、“转化意图词”），查看导入或拓展保存的关键词列表。
* **主要指标**：展示每个词的“传统检索指数”、“大模型提及概率”与“商业价值评分”，支持批量删除、分类转移和一键导出。

### 1.2 热度指数 (指数查询)
* **用户路径**：输入单个或批量关键词，点击查询。
* **业务产出**：集成各大引擎的实时热度指数（如百度指数、微信指数、大模型检索估算频次）。展示趋势走势图，帮用户筛选高商业回报率的“黄金词”。

### 1.3 AI 智能拓词 (语义拓展)
* **用户路径**：输入一个种子关键词（如“低代码平台”），选择“拓展方向（如：比价意图、选型对比、痛点提问）”，点击拓词。
* **业务产出**：大模型根据语义深度挖掘用户在面对 LLM 时可能使用的口语化提问句式（如：“市面上有哪些适合小团队且不限人数的免费低代码平台？”），批量展示并支持一键勾选存入词库管理。

### 1.4 规则拓词 (规则拓词)
* **用户路径**：利用排列组合批量造词。用户配置三个词栏：
  * 前缀词栏（例如：“哪里有”、“如何评价”、“好用的”）
  * 核心词栏（例如：“CRM系统”、“进销存软件”）
  * 后缀词栏（例如：“推荐”、“多少钱”、“哪个好”）
* **业务产出**：系统执行笛卡尔积乘积组合，批量拼接出如“好用的进销存软件哪个好”、“如何评价CRM系统多少钱”等矩阵词。

## 2. 🛠️ 技术实现方案

### 2.1 传统指数与 AI 指数获取
* **传统指数**：通过对接第三方 SEO 接口服务（如 5118 API、站长之家 API 或 Ahrefs API），拉取百度指数、谷歌月搜索量。
* **AI 检索估算指数（GEO核心指标）**：由于大模型（如 OpenAI）没有公开的关键字搜索量，本系统设计了一套**基于大模型共现率估算的 AI 搜索指数模型**。
  * **算法原理**：将种子词放入大模型预热向量库，在特定垂直领域的标准 QA 集中进行检索，根据共现密度及语义相关度，输出一个估算的 `GEO 指数值`（1-10分制，分数越高代表在生成式问答中被唤醒的概率越高）。

### 2.2 AI 智能拓词 Prompt 模板
拓词的精髓在于模拟用户对大模型的提问习惯。后台大模型调用 Prompt 如下：
```text
你是一个精通 GEO (生成式引擎优化) 的关键词专家。
请根据种子词【{seed_word}】，以及用户指定的提问意图【{intent_type}】，拓展出 20 个用户在向 ChatGPT、Gemini 等 AI 提问时最可能使用的口语化长尾问题。

要求：
1. 必须是完整的问句，符合人类向 AI 提问的日常对话习惯（不要像传统百度搜索一样只输出词组）。
2. 句式多样，包含“怎么”、“哪些”、“为什么”、“推荐”、“评价”等疑问词。
3. 请以标准的 JSON 数组格式输出，格式为：["问题1", "问题2", ...]。不要有任何多余的解释文字。
```

## 3. 💾 数据库表设计 (DDL)

### 3.1 词库管理库表 (`geo_keyword`)
```sql
CREATE TABLE `geo_keyword` (
  `keyword_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '关键词ID',
  `keyword_text` varchar(200) NOT NULL COMMENT '关键词/问句内容',
  `category_id` bigint(20) DEFAULT '0' COMMENT '所属词库分类ID',
  `search_volume` int(11) DEFAULT '0' COMMENT '传统搜索引擎月检索量',
  `geo_index` decimal(3,1) DEFAULT '0.0' COMMENT 'GEO/AI搜索唤醒指数（1.0-10.0分）',
  `competition_level` varchar(20) DEFAULT 'medium' COMMENT '竞争烈度（high高 medium中 low低）',
  `status` char(1) DEFAULT '0' COMMENT '词汇状态（0正常 1停用）',
  `create_dept`      bigint(20)                       COMMENT '创建部门',
  `create_by`        bigint(20)                       COMMENT '创建者',
  `create_time`      datetime                         COMMENT '创建时间',
  `update_by`        bigint(20)                       COMMENT '更新者',
  `update_time`      datetime                         COMMENT '更新时间',
  `del_flag`         char(1)          DEFAULT '0'     COMMENT '删除标志（0代表存在 1代表删除）',
  PRIMARY KEY (`keyword_id`),
  UNIQUE KEY `uni_keyword_text` (`keyword_text`),
  KEY `idx_category_id` (`category_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='GEO核心关键词表';
```

### 3.2 拓词历史日志表 (`geo_keyword_expansion_log`)
```sql
CREATE TABLE `geo_keyword_expansion_log` (
  `log_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '日志ID',
  `seed_word` varchar(150) NOT NULL COMMENT '输入的种子词',
  `expansion_type` varchar(50) DEFAULT 'ai' COMMENT '拓展方式（ai智能 rule规则拼装）',
  `result_count` int(11) DEFAULT '0' COMMENT '拓展出的词汇总数',
  `expanded_results` text COMMENT '拓展结果JSON列表，格式如 ["问题1", "问题2"]',
  `create_dept`      bigint(20)                       COMMENT '创建部门',
  `create_by`        bigint(20)                       COMMENT '创建者',
  `create_time`      datetime                         COMMENT '创建时间',
  `update_by`        bigint(20)                       COMMENT '更新者',
  `update_time`      datetime                         COMMENT '更新时间',
  `del_flag`         char(1)          DEFAULT '0'     COMMENT '删除标志（0代表存在 1代表删除）',
  PRIMARY KEY (`log_id`),
  KEY `idx_seed_word` (`seed_word`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='关键词拓展日志表';
```
